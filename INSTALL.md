# Установка и запуск агента

## 1. Что нужно

- Python 3.9+
- пакеты `openpyxl` (чтение и запись `.xlsx`) и `xlrd` (если выгрузки приходят
  в старом `.xls`)
- агентное пространство GigaCowork (или любой harness с файлами и запуском
  скриптов: Claude Cowork, Goose, Manus, свой скрипт вокруг API модели)

```bash
python3 -m venv .venv
.venv/bin/pip install openpyxl xlrd
```

Сеть не используется, внешние сервисы и коннекторы не нужны.

## 2. Установка навыка в GigaCowork

1. Взять архив `agent_gigacowork.zip` (внутри папка `ful-order-distribution/`).
2. Загрузить навык в пространство: **Навыки → Загрузить навык** (или распаковать
   папку в каталог навыков пространства).
3. Создать агента и вставить в поле системного промпта содержимое
   `system_prompt.txt`.
4. Подключить к агенту навык `ful-order-distribution`.
5. Проверить, что в окружении агента доступен Python и `openpyxl`
   (команда `python3 -c "import openpyxl"`).

## 3. Запуск «без текста запроса»

1. Выбрать агента.
2. Приложить три файла Excel в любом порядке:
   - выгрузка ФУЛ из 1С,
   - реестр Cloud,
   - сотрудники из 1С.
3. Отправить пустое сообщение (если интерфейс не позволяет — отправить любое
   сообщение без описания задачи, например «.», агент всё равно запускает
   навык).

Агент сам определит, какой файл чем является, по заголовкам колонок.

## 4. Ручной запуск скрипта (проверка без платформы)

```bash
python3 scripts/ful_distribution.py \
  --files ful.xlsx cloud.xlsx staff.xlsx \
  --out ./out
```

или с явными ролями:

```bash
python3 scripts/ful_distribution.py \
  --ful ful.xlsx --cloud cloud.xlsx --staff staff.xlsx --out ./out
```

Скрипт печатает JSON со сводкой и готовую строку ответа для чата.
Результат: `./out/result.xlsx`.

Коды возврата: `0` — успех, `2` — не хватает файлов или обязательных колонок
(в сообщении перечислено, каких именно).

## 5. Что получится в файле

| Лист | Что внутри |
| --- | --- |
| Новые строки Cloud | готовые строки по 12 колонкам формы реестра |
| Повторные отправки | заказы, которые уже есть в Cloud, и комментарий для них |
| Возможные пропуски | ФУЛ раньше последней записи Cloud |
| Требует внимания | заказы, по которым нужно решение человека, с причиной |
| Журнал решений | каждый ФУЛ пачки: тип, группа, логист, обоснование |
| Сводка | счётчики |

Красным подсвечены значения `не определено`, жёлтым — строки без логиста.

## 6. Проверка после установки

```bash
python3 tests/run_checks.py --runs 3        # метрики и 3 прогона
python3 tests/test_header_robustness.py     # «чужие» файлы: другой порядок колонок
```

Ожидаемый вывод: 24/24 совпадений с эталоном, 0 выдуманных значений,
одинаковый результат между прогонами, время < 60 с.

## 7. Работа через GigaChat API (вариант из ТЗ)

Скрипт навыка не требует модели. Если harness не нужен, ответ в чат можно
получать напрямую от GigaChat:

1. Получить Authorization key в личном кабинете developers.sber.ru
   (тариф для физических лиц, Freemium), сохранить в переменную
   `GIGACHAT_AUTH_KEY` или в файл `~/.gigachat_key` (права 600).
2. Один раз собрать CA-бандл с корневыми сертификатами Минцифры
   (без них TLS к `*.sberbank.ru` не проверяется):

   ```bash
   curl -sS -o /tmp/root.crt https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt
   curl -sS -o /tmp/sub.crt  https://gu-st.ru/content/lending/russian_trusted_sub_ca_pem.crt
   sed -i 's/\r$//' /tmp/root.crt /tmp/sub.crt
   sed -i 's/-----END CERTIFICATE-\{5,\}/-----END CERTIFICATE-----/' /tmp/root.crt /tmp/sub.crt
   mkdir -p ~/.config/gigachat
   cat /etc/ssl/certs/ca-certificates.crt /tmp/root.crt /tmp/sub.crt \
     > ~/.config/gigachat/ca-bundle.pem
   ```

3. Запуск:

   ```bash
   python3 tests/gigachat_run.py --files ful.xlsx cloud.xlsx staff.xlsx \
     --out out/gigachat --model GigaChat-2-Max
   ```

Скрипт получает access token (`POST /api/v2/oauth`, scope `GIGACHAT_API_PERS`,
токен живёт 30 минут), выполняет навык и просит модель сформулировать ответ
по шаблону. Ключ и токен в репозиторий не попадают.

## 8. Типовые проблемы

| Симптом | Причина | Что делать |
| --- | --- | --- |
| «не найдены обязательные колонки» | в файле нет колонки с номером заказа/поставщиком, либо заголовки на другом листе | проверить выгрузку; при нестандартном названии колонки добавить синоним в `references/dictionaries.md` и в `ALIASES` скрипта |
| «нужно три файла» | приложено меньше трёх | приложить все три выгрузки |
| `ModuleNotFoundError: openpyxl` | не установлены зависимости | `pip install openpyxl xlrd` |
| Все логисты `не определено` | в списке сотрудников нет состояний «Работает» или должности не совпадают с группами | проверить колонки «Текущее состояние» и «Должность» |
