# Распределение ФУЛ между логистами

## Когда применять

Навык запускается, когда в чат приложены **три файла Excel** и нет текста запроса
(или просьба звучит как «распредели заказы», «подготовь строки Cloud»,
«найди повторные отправки»):

1. выгрузка упаковочных листов из 1С (по строке на ФУЛ);
2. реестр заказов Cloud (история заказов);
3. список сотрудников из 1С (ФИО, состояние, должность, таб. номер).

Текст запроса для запуска не нужен: достаточно выбора агента и трёх файлов.

## Как запустить

Один вызов скрипта. Роли файлов определяются по заголовкам, порядок файлов
и их имена значения не имеют:

```bash
python3 scripts/ful_distribution.py \
  --files /путь/файл1.xlsx /путь/файл2.xlsx /путь/файл3.xlsx \
  --out /путь/папка_результата
```

Если известно, какой файл чем является, можно указать явно:

```bash
python3 scripts/ful_distribution.py \
  --ful /путь/ful.xlsx --cloud /путь/cloud.xlsx --staff /путь/staff.xlsx \
  --out /путь/папка_результата
```

Скрипт печатает JSON со сводкой и строку-ответ для чата, результат сохраняет
в `<папка_результата>/result.xlsx`. Никаких сетевых вызовов и записи во внешние
системы нет: только чтение приложенных файлов и запись одного xlsx.

Требования к окружению: Python 3.9+, пакет `openpyxl` (для `.xls` — `xlrd`).

## Что делает скрипт

1. Находит в каждой книге лист и строку заголовков, сопоставляет колонки
   **по названиям** (синонимы — в `references/dictionaries.md`), лишние колонки
   и другой порядок не мешают.
2. Определяет статус каждого ФУЛ: новый заказ / повторная отправка /
   дубль внутри пачки / ошибка данных.
3. Назначает группу: `air` → авиаперевозки; не `air` + Китай (включая Гонконг)
   → ВЭД; не `air` + не Китай → мультимодальные перевозки.
4. Выбирает логиста: чаще всех работавший с поставщиком в истории Cloud;
   если он в отпуске, уволен или его нет — наименее загруженный в группе
   по заказам «в работе». Один поставщик в пачке — один логист.
5. Пишет `result.xlsx` с листами: «Новые строки Cloud» (12 колонок формы
   реестра), «Повторные отправки», «Возможные пропуски», «Требует внимания»,
   «Журнал решений» (обоснование по каждому ФУЛ), «Сводка».

Полные правила и допущения — `references/rules.md`, форма реестра —
`references/cloud_form.md`.

## Как ответить пользователю

После успешного запуска — короткий ответ по шаблону, без пересказа всех строк:

```
Готово: новых строк — {new_rows}, повторных отправок — {repeats},
требуют внимания — {attention}.
Файл: {путь к result.xlsx}
```

Допускается добавить одну строку о самом важном: например,
«в группе ВЭД нет доступных логистов — 2 заказа без логиста».
Не перечисляй все заказы и не цитируй журнал: он в файле.

## Жёсткие ограничения

- Решения о группе и логисте принимает **скрипт**, а не модель. Не меняй
  назначения «по смыслу» и не предлагай своих логистов.
- Если данных нет (номер заказа, страна, способ доставки, доступные логисты),
  в результате остаётся `не определено` и причина. **Не придумывать**
  правдоподобные значения и не подставлять сотрудников из других групп.
- Ничего не записывать в 1С, Cloud, почту; не отправлять уведомления.
- Если скрипт вернул ошибку о ненайденных колонках — перечисли, каких колонок
  не хватает, и попроси файл с корректной выгрузкой. Своими силами колонки
  не «додумывать».
- Запускать скрипт один раз на пачку; повторный запуск нужен только после
  замены файлов.
