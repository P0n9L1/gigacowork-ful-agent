# Правила распределения и принятые допущения

Документ описывает, что именно делает `scripts/ful_distribution.py`.
Правила, помеченные «допущение», в БТ не описаны буквально и вынесены
в открытые вопросы к заказчику (см. раздел 5 отчёта).

## 1. Статус ФУЛ

| Условие | Статус | Действие |
| --- | --- | --- |
| в комментарии нет номера заказа | ошибка данных | строка Cloud не создаётся, ФУЛ в «Требует внимания» |
| номер заказа уже встречался в этой пачке | дубль в пачке | строка не создаётся, в «Требует внимания» |
| номер заказа уже есть в реестре Cloud | повторная отправка | новая строка не создаётся; в «Повторные отправки» пишется комментарий «Повторная отправка ФУЛа, ДД.ММ.ГГГГ» (дата ФУЛ) |
| заказа нет ни в пачке, ни в Cloud | новый заказ | формируется строка Cloud |

Номер заказа ищется регулярным выражением по маске `S0001234`
(регистр и пробелы внутри не важны). Номер ФУЛ на статус не влияет.

## 2. Группа логистов

| Способ доставки | Страна отправления | Группа |
| --- | --- | --- |
| `air` (в любом написании) | любая, в том числе пустая | Авиаперевозки |
| не `air` | Китай, Гонконг, Макао, CN, КНР, China | ВЭД |
| не `air` | любая другая страна | Мультимодальные перевозки |
| не `air` | страна пустая | не определено → строка не создаётся |
| способ доставки пустой | любая | не определено → строка не создаётся |

Приоритет: способ доставки важнее страны. `air` из Гонконга — авиаперевозки,
а не ВЭД.

## 3. Кого нельзя назначать

- состояние в 1С: «Уволен», любой отпуск (в том числе по уходу за ребёнком,
  без сохранения зарплаты), больничный — недоступен;
- должность ассистента или руководителя — не распределяет заказы;
- должность вне трёх групп — не участвует.

Доступен только сотрудник со состоянием «Работает» и должностью одной из трёх
групп.

## 4. Выбор логиста

1. **История с поставщиком.** Считаются все заказы этого поставщика в реестре
   Cloud (любой статус) по каждому логисту. Побеждает логист с наибольшим
   числом заказов. При равенстве — у кого более свежая дата получения УЛ,
   затем меньше текущая загрузка, затем ФИО по алфавиту.
2. **Предпочтительный логист недоступен** (отпуск, уволен, другой группы,
   нет в списке сотрудников) — берётся **наименее загруженный** сотрудник
   группы. Второй по истории не выбирается: в БТ сказано «при недоступном
   логисте — наименее загруженного».
3. **Новый поставщик** (нет в Cloud) — сразу наименее загруженный в группе.
4. **Загрузка** — число заказов этого логиста со статусом «в работе» в реестре
   Cloud на момент старта пачки. Назначения внутри пачки увеличивают загрузку:
   следующий заказ видит уже обновлённый счётчик.
5. **Один поставщик в пачке — один логист.** Поставщик сравнивается без учёта
   регистра, кавычек, дефисов, лишних пробелов и орг-формы (ООО, АО, ИП, LLC).
   Первый назначенный логист фиксируется и используется для остальных заказов
   этого поставщика в пачке.
6. **Если в группе нет доступных логистов** — логист `не определено`, строка
   Cloud создаётся, ФУЛ попадает в «Требует внимания». В другую группу заказ
   не передаётся (требование БТ).

## 5. Сопоставление имён

В Cloud логисты записаны коротко («Иванов А.П.»), в 1С — полным ФИО.
Сопоставление: фамилия + инициалы. Если подходящих сотрудников несколько —
сопоставление не выполняется (загрузка и история по такому имени не считаются),
чтобы не приписать заказы не тому человеку.

В новых строках логист пишется так же, как он записан в Cloud (короткое имя),
чтобы реестр оставался однородным; для нового сотрудника — полное ФИО из 1С.

## 6. Возможные пропуски

ФУЛ считается возможным пропуском, если заказа нет в Cloud, а дата ФУЛ
**раньше** максимальной «Даты получения УЛ» в реестре: по логике процесса
такой заказ должен был попасть в Cloud раньше.

Допущение: строка Cloud для такого ФУЛ формируется (заказ реально новый),
но ФУЛ попадает в «Возможные пропуски» и «Требует внимания» с пометкой
в комментарии — окончательное решение за сотрудником.

## 7. Форма строки Cloud

12 колонок в порядке реестра. Заполняются: Заказ, Поставщик, Бренд, Логист,
Статус = «в работе», Cut-off (из ФУЛ), Дата получения УЛ (дата ФУЛ),
Страна отправления, Способ доставки.

Не заполняются: «Дата подтверждения», «Документы получены» — этих событий
ещё не было, подставлять дату нельзя.

Способ доставки приводится к каноническому написанию (`air`, `sea`, `truck`,
`direct truck`, `railway`). Страна — к написанию из справочника
(`China` → `Китай`); если страны нет — `не определено`.

## 8. Детерминированность

ФУЛ обрабатываются в порядке (дата ФУЛ, номер ФУЛ). Все тай-брейки заданы
явно (свежесть, загрузка, алфавит), поэтому три запуска на одних файлах
дают побайтово одинаковое содержимое результата.
